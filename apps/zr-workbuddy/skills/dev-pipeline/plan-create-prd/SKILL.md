# 需求理解 · PRD-lite（改编自 Cole · plan-create-prd）

## 何时用
- 一体化第 **2** 步；第 1 步 raw_intake 已落盘

## 输入
- `artifacts.raw_intake`（用户原话）
- Epic 元数据（标题提示等）

## 做什么（完整过程）
1. Skill 横幅：整理「做什么 / 为何 / 怎么验收 / 场景化交付」  
2. 从原文提炼 `goal`、验收列表、非目标  
3. **推断开发场景**（灵活，非单一模板），例如：  
   - 新功能全栈页 · 前端/UI · 后端/接口 · 修 bug · 重构  
   - 既有增强 · 占位 · 配置/文案 · 脚本/CI · 自适应最小改动  
4. 写入 `delivery` + `scenario` + **`scope`（范围内条目 / 禁止项 / 变更文件上限）**  
5. 冻结 `prd_rev`

## 禁止
- 禁止把「菜单+路由+页面+接口」套死到所有需求  
- 禁止直接改仓库  
- 开跑前勿用多选澄清卡抢 UI（场景由本步推断）

## PASS / FAIL
| | 条件 |
|---|---|
| **PASS** | 产出带版本号的 PRD-lite，含 scenario/delivery，且至少一条验收标准 |
| **FAIL** | 无法提炼任何可验收目标 |

## 用户在时间线看到什么
- 目标、**场景名**、推断依据、交付范围、验收、prd_rev
