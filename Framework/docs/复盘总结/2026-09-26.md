- **Runner**：后台线程注册/取消/孤儿 Run 回收；`timeline_trace` 记录回退与多轮 5·2/6·2/7·2。

## 4. 代码审查（必要 / BUG / 安全）

### 4.1 架构必要性（保留）

| 模块 | 结论 |
|------|------|
| `dev_pipeline/*` + `features/dev-pipeline` | **必要**：一体化唯一编排面，不新增第二 bridge |
| `timeline_trace.py` / `fix_loop.py` | **必要**：回退可视化 + 自动修环，否则 UI 与产品承诺不一致 |
| `lane_exec.py` 薄封装 | **必要**：7～10 复用审码/提交/部署，避免在 steps 里 duplicate |
| 前端 `dpFormatReviewDisplay` 等 | **必要**：旧 Run 无 `report_body`、宿主样式不可控，纯后端无法单独解决展示 |

可后续删减（非阻塞）：`dpExtractReviewOverall` 若全部 Run 都有短 summary + report_body，UI 旧数据兼容层可收敛。

### 4.2 已修 BUG

- **`get_config` 绑定失效**：runner/steps 改为 `dp_config.get_config()`，单测 mock 与运行时改配置一致。

### 4.3 安全（回环信任模型下）

| 项 | 评估 | 说明 |
|----|------|------|
| API 无 run↔session 绑定 | **已知风险 / P2** | 知 `run_id` 可 cancel/advance；依赖回环 + 随机 `dpj-` id。企业暴露需加 session 校验或 HITL nonce |
| `workspace` / 审码路径 | **可控** | `resolve_workspace`、`_normalize_review_files` 拒 `..` 与绝对路径 |
| SSE/日志泄密 | **可控** | 报告正文 cap；Job 日志仍须遵守现有脱敏规则 |
| 一体化误触四车道 | **可控** | `auto_run` 与 HITL 分轨；聊天审码卡仍独立入口 |
| 提交/部署 | **同四车道** | 仍走既有 confirm/门禁，未绕过 |

**未改（刻意）**：不为一体化单独立 HTTP token；与 `workbuddy-security-enterprise.mdc` 一致。
