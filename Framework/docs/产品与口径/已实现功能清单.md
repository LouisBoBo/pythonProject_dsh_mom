## 1. 登录、人员与能力开关

**用途**  
本机账号登录后才能用聊天与管理功能。管理员维护人员、重置口令，并按人开关问数、PCB、写码、审码、提交、部署、需求到上线、视觉识图、连接配置。

**实现**  
- 账号：`engine/app/auth/`（登录、改密、登出、人员增删改、启停、重置口令、能力写入）。  
- 聊天挡板：`plugins/mes-bridge/client-src/login.js`，打开 3081 即要求登录。  
- 管理页「人员和角色」：引擎静态页，管理员可见。  
- 拦截：`deny_if_user_blocked`；写码另走 `coding_mutex`，未开通则拦对话写码。

**用法**  
1. 打开 3081，用本机账号登录。  
2. 管理员在人员页新增同事、分配角色、勾选或关闭单项能力。  
3. 本人可改自己的密码；停用账号无法再登录。

## 2. 配置中心

**用途**  
把 Key、业务连接、写码、部署、品牌和首次向导收在一处。保存 DeepSeek Key 后，聊天凭据会同步到本机 DSH，不必再去宿主「设置 → 模型」填第二份。

**实现**  
- 读写：`engine/app/config_store.py`，真相文件 `engine/config/config.yaml`。  
- 聊天设置页：`client-src/settings.js`，分栏为应用配置、MES 连接、商用模型、远端审码、写码、自动化部署、自动化推送。  
- Key 同步：`engine/app/dsh_chat_credential.py`。  
- 首次向导：`engine/app/setup_wizard.py`，完成后可摸底项目画像。  
- 连接自检工具：已启用的 `features/mes-config`（`mes_config` / `mes_status`）。

**用法**  
在 3081 打开 WorkBuddy 设置，按栏填写并保存：

| 栏 | 填什么 |
|----|--------|
| 应用配置 | 产品名、Logo |
| MES 连接 | 业务系统地址；可上传 / 粘贴 / 从 URL 导入接口文档与数据字典 |
| 商用模型 | DeepSeek 或 OpenAI 兼容接口的 Key |
| 写码 | Cursor 写码相关项 |
| 自动化部署 | 是否开启、是否一体部署、远端与环境 |
| 自动化推送 | 企微群机器人、飞书多维表格（可只开一个） |
| 视觉模型 | 智谱 GLM-4V、Qwen-VL 或自定义 |

对话里也可以说「测一下连接 / 看连接状态」，由 `mes_config`、`mes_status` 去测 MES 与模型。

## 3. 自然语言问数（mes-ask）

**用途**  
用中文问产量、良率、OEE、缺陷、工单等，返回合计、明细表和图表。配置中心已导入的只读 OpenAPI（保养计划、仓储等）也能问。

**实现**  
- 工具：`features/mes-ask` → `mes_ask`（必须注入 `tools` + `attachments` 才能出图）。  
- 算数：`engine/app/ask_data.py`、`nl_engine.py`、`ask_api_route.py`、`analyzer.py`、`detail_list.py`。  
- 问「多少 / 汇总 / 对比」走合计；问「明细 / 列表 / 计划」走记录列表（最多 50 条）。追问时可带上文，避免「工单」打到保养工单。

**用法**  
在 3081 直接问，例如：「今日再制品工单有多少个」「查询设备保养计划」「查今日在制品工单明细」。同一会话接着追问即可。

## 5. 本机审码（code-review）

**用途**  
对人选定的本机工程做代码审查，出风险报告。直读源码，不依赖 Git 状态，也不走编辑器桥。

**实现**  
- 工具：`mes_code_review_begin` / `status` / `check` / `list` / `run` / `report`。  
- 引擎：`engine/app/code_review/`（路径校验、文件列表、LLM 审查、报告落盘）。  
- 路径须经选目录确认签发 `path_ticket`，模型不能自填任意绝对路径开跑。  
- 聊天卡：`client-src/lanes/code-review.js`。报告可进资料库。

**用法**  
1. 在对话说「审核这段代码」或「看看这次改动」。  
2. 在主聊天卡片里选工程目录和文件（可写审查重点）。  
3. 确认后等待审查卡；需要旧报告时按报告号再查。

## 6. 人触发提交（code-commit）

**用途**  
人确认后，把选定文件提交到本机 Git（可 push）。模型不执行 git。提交前有阻断式门禁；被拦住时可生成写码修复卡。

**实现**  
- 工具：`mes_code_commit_begin` → `start` / `prepare` / `confirm`，以及 `push_retry`、`prepare_fix`、`job`。  
- 引擎：`engine/app/code_commit/`（`git_ops.py`、`svn_ops.py`、门禁 `skill_review.py`）。  
- 确认接口校验 UI 签发的一次性票据（HITL nonce）。  
- 聊天卡：`client-src/lanes/code-commit.js`。

**用法**  
1. 说「提交代码」。  
2. 在卡片里选仓库、勾选文件、写中文说明、选择是否推送。  
3. 门禁通过后再点确认。若只是推送失败、本地已经 commit，可以说「重试推送」。

## 7. 一体部署（code-deploy）

**用途**  
人确认后，把本机工程按单元增量或全量同步到测试 / 预发环境。生产环境名被拒绝。探活失败会回滚，避免「文件同步了但服务挂了」被当成成功。

**实现**  
- 工具：`mes_code_deploy_begin` / `status` / `prepare` / `confirm`。  
- 引擎：`engine/app/code_deploy/`（单元划分、SSH/rsync、部署前快照、探活、失败回滚）。  
- 一体部署（`unified_product`）默认同步并拉起远端引擎与聊天壳；可在配置里关掉，只同步业务文件。  
- 确认同样要 HITL nonce。聊天卡：`client-src/lanes/code-deploy.js`。

**用法**  
1. 设置里打开「自动化部署」，填好远端与默认工程。  
2. 对话说「部署到预发」。  
3. 在确认卡上看全量或增量、勾选单元，确认后等结果卡。无探活地址时不会记成部署成功。

## 8. 需求到上线（dev-pipeline）

**用途**  
把「一句话或一张图」编排成一条流水线：采集需求 → 理解 → 读项目 → 出方案 → 写代码 → 验证 → 复核 → 提交 → 开 PR → 部署到测试环境。它调度既有写码插件和审码 / 提交 / 部署，不另做一套 git 或 SSH。

**实现**  
- 开关：输入框旁绿色「需求→上线」。会话级状态由引擎 `session_mode` 记住。  
- 工具：`mes_dev_pipeline_begin`（唯一开跑入口）、`status`、`advance`（重试当前步）、`confirm_step`、`cancel`。  
- 编排：`engine/app/dev_pipeline/`。步骤定义在 `ops.py` 的 `STEP_DEFS`：

  | 步 | 现在界面上的名字 | 实际做什么 |
  |----|------------------|------------|
  | 1 | 需求采集 | 收下原文；绿开关打开时合并聊天附图并识图 |
  | 2 | 需求理解 | 整理成可实施说明 |
  | 3 | 读库上下文 | 看当前工程结构和相关文件 |
  | 4 | 规划实现 | 改动范围与验证方式 |
  | 5 | 写代码（Cursor 插件） | 调 Cursor 对话写码真任务改文件 |
  | 6 | 验证 | 跑配置的检查命令，只认过 / 不过 |
  | 7 | 复核 | 复用审码，只看本次改动 |
  | 8 | 提交 | 复用提交车道 |
  | 9 | 开 PR | 按 `pr_provider`；SVN 仓库标为不适用 |
  | 10 | 部署上线 | 复用部署车道，终点是测试环境 |

- 默认 `auto_run: true`：开跑后 1～10 自动连跑。空改动最多打回 3 轮，不能把「任务成功但没有文件变化」当成做完。  
- 过程流只画已经发生的步骤和当前步：`client-src/lanes/dev-pipeline.js`。进度用 SSE。

**用法**  
1. 打开输入框旁绿色「需求→上线」。  
2. 发文字，或贴界面截图，或两者一起发。  
3. 看同一张过程流卡。要改需求就再发一条，会新开一轮并带上本会话上一轮上下文。  
4. 绿开关关掉时，同一句话走第 9 节的普通写码，不会进这条流水线。

## 9. Cursor 对话写码（普通写码）

**用途**  
绿开关关闭时，用对话改本机工程：改页面、改菜单、加功能、按截图改。体验接近在 Cursor 里聊天改代码。人确认后才改盘。

**实现**  
- 产品入口是插件市场里的 **Cursor 对话写码**（`@zhongruan/dsh-cursor-chat`）。本仓 `mes-bridge` 只做意图分流：普通写码必须先调该插件的 begin 工具。  
- 本仓 `features/code-dev`（`mes_code_dev_*`）和更早的写码卡仍留在源码里，**当前 `plugins.json` 未启用**，路由明确要求不要再走它们。  
- 一体化第 5 步由 `engine/app/dev_pipeline/cursor_coding_client.py` 调同一套写码任务，不在流水线里再写一个改文件引擎。  
- 写码配置、讨论卡、任务查询与进度流仍在 `engine/app/code_dev/`，供插件与旧车道读取。  
- 项目画像（`engine/app/project_profile/`）给写码提供当前工程是什么技术栈、目录怎么长。

**用法**  
1. 设置 → 插件市场，安装并启用「Cursor 对话写码」。  
2. 确认输入框旁是「普通写码」（绿色「需求→上线」关掉）。  
3. 选好顶栏工作区，直接说要改什么；有截图就贴在同一条消息里。  
4. 在插件给出的确认卡上点确认，然后看进度。未安装该插件时，对话不会改你的工程。

## 10. 视觉识图（vision）

**用途**  
独立识图：上传图片，按提示词或用途（需求采集 / 通用）返回文字理解。一体化采集步骤会用它读截图；其它业务也可以复用。

**实现**  
- 工具：`mes_vision_status`、`mes_vision_understand`。  
- 引擎：`engine/app/vision/`（配置、上传、待用附图、识图调用）。供应商在设置里选智谱、Qwen-VL 或自定义。  
- 普通写码贴图由对话写码插件自己看图，不强制先走本工具。

**用法**  
- 开「需求→上线」后直接贴图，采集步会自动带上。  
- 或在对话里明确要求识图，并给出图片。  
- 先在设置里配好视觉模型，否则状态工具会报未就绪。

**用法**

## 16. 功能热插拔与第三方功能包

**用途**  
自有业务能力可以单独开、关，大约一秒生效，不必重启聊天壳。符合契约的第三方包可以打成 zip 装进 `features/`。

**实现**  
- 真相文件：`engine/data/plugins.json`，bridge 轮询热加载。  
- 接口：列表、启用、停用、安装前校验、安装、卸载。  
- 管理页：「功能插件」；命令：`scripts/plugin.sh --app zr-workbuddy …`。  
- 契约：目录内要有 `index.js` + `manifest.json`，经 `mesEngine` 调引擎，不能在功能包里直接 import npm。  
- DSH 市场上的 Cordis / Skill / MCP 不走这条 zip，走第 17 节插件中心。

**用法**  
管理页或 `plugin.sh enable|disable <id>`。装第三方功能包时先校验 zip，再安装，然后在列表里打开开关。

## 17. 公司插件市场与宿主接线

**用途**  
在 3081 设置里安装中软私有插件（对话写码、知识库、用量计量等），同时保留官方目录。裸聊天壳没有「插件市场」入口，第一次接线会预装市场 UI。

**实现**  
- 启动前合并公司登记地址，失败则不起聊天壳：`scripts/lib/company_dsh_market.sh`。  
- 市场 UI：`scripts/lib/ensure_dshmarket.py`。  
- 知识库预装接线见 `Framework/docs/功能实现/知识库预装方案.md`（插件本体在独立仓，本仓只钉版本与默认开关）。  
- 新机依赖（Python、Node、工具运行时、Key、市场）由 `scripts/lib/ensure_runtime.py` 在启动前检查，修不了就拒绝启动。

**用法**  
日常打开 3081 → 设置 → 插件市场，搜索后安装，状态变为运行中再回对话使用。第一次在仓库根执行 `scripts/host.sh wire` 然后 `scripts/host.sh up`。

侧栏还会出现市场插件自己的入口（知识库、自动化、专家技能）。它们和资料库、用量互斥：打开其中一个会收起另一个，避免叠成白屏。

## 18. 桌面壳

**用途**  
给不习惯开终端的同事一个安装包：冷启动能看见启动页再进主界面，关窗口进托盘不退出，再次点图标只恢复一个窗口，并可检查新版本、下载后由人确认安装。

**实现**  
- `desktop/main.js`：单实例锁、窗口创建即显示、启动页加载完成后再打开主页、托盘「打开 / 退出」。  
- 更新：拉公司服务器上的 `latest-*.json`，全量下载安装包，人确认后拉起安装向导。远端最多留两个版本的安装包。  
- 打包上传：`scripts/lib/package_desktop.py` 成功后自动传到桌面发布目录。
