## A. 写好（质量与第一次命中）— 优先

| 方向 | 为何重要 | 本仓可做 | 注意 | 落地对照 |
|------|----------|----------|------|----------|
| **工程画像进写码** | Agent 不知道目录/栈/入口，易改错层 | 已有 directory portrait 钩子可加强：进 begin/continue 的强制短画像（框架、前后端根、禁改路径） | 勿焊死某一家 ERP | **已做透** → 清单 Q0-3：通路（pre-execute/execute）+ `formatCodingPortraitBlock`（栈/前后端根/目录要点/通用禁改）；分诊 `formatDirectoryBlock` 未改 |
| **验收标准进诉求** | 「写好」= 用户能验 | 提示词要求结论带「怎么打开/点哪里看」；可选把用户原话里的验收句钉进 handoff | 跳过了 P2-1 收短，但「可验」仍值得做 | **已做透** → Q0-4 结论文案 + Q1-3 `coding-acceptance` 钉进 message/handoff |
| **改动范围门禁** | 防大面积乱改 | 提示：优先最小 diff；续改禁止重做已同步文件 | 真·文件级限额多半在插件 | **已做（提示层）** → 清单 Q1-1；硬限额仍属插件仓 |

| **贴图→定位** | 常见修 UI/报错 | 附图本地化已有；可加强「先指区域再改」的提示 | 识图能力在插件/SDK | **已做** → 清单 Q1-2（【贴图定位】+ 提示词；不改识图） |

## C. 能用（产品体感）— 要取舍

1. **确认卡摩擦**：保留 HITL 是安全底线。本仓只能把卡说清楚；「少点一次」要破窗。  
2. **网络重试**：本仓只能指引续改；真·自动重试在插件/SDK，需去插件仓或允许破窗。  
3. **同步跳过 \*.db**：插件仓事项；本仓已用回收兜底。  
4. **进度可见**：阶段（沙箱 / Agent / 同步）更清晰，用户才敢当工具用——可只做文案/横幅，不改插件协议。

（C 类默认**不进本仓执行板**，除非用户明确破窗或单独立「进度文案」条。）
