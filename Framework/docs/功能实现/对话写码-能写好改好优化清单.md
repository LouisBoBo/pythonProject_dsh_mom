## 0. 目标与硬边界

**目标**：把对话写码做成**能用的写码工具**——不仅能开写，还要**写好（落盘诚实、可验收）**、**改好（成功/失败续改都有上下文）**。

**硬边界（每条落地时一律不得削弱）**：

1. **不改** DSH 写码插件 / 市场 Bundle / `~/.dsh/**/node_modules`。  
2. **不削弱 HITL**：确认卡仍须人点；禁止自动点确认、禁止 `confirmed=true` 偷开工。  
3. **不影响其它正常功能**：问数、审码、提交、部署、一体化、资料库、用量、公司市场等路径不得因本清单改坏。  
4. **第一次就要做对**：先读 Job / 现有钩子证据再改；每条必跑 `node scripts/lib/run_coding_hard_pit_tests.mjs`；改 `client-src` 须 `build:client`。  
5. **只做当前一条**；禁止顺手大重构。

**本仓可改**：`apps/zr-workbuddy/plugins/mes-bridge/`、本清单与索引；引擎仅当本条明确需要时才动。

### 2.1 Q0 · 写好 / 改好（按序做）

- [x] **Q0-1　落盘诚实（禁止假成功收尾）**  
  - **现象**：插件 `status=succeeded` 但有效 `synced_files`（剔 \*.db）为空时，仍像「已经做完了」，同句续改还会被 dup-guard 当成功拦住。  
  - **本仓做**：  
    1. `formatFriendlyCodingCloseout`：识别「空同步成功」→ 明确「未检测到源码落盘 / 不要当已修好」，引导 `continue` + `parent_job_id`  
    2. `duplicateCodingConfirmBlock`：空同步成功 + 同句 → **放行 continue**（仍 HITL）；可选拦无故 begin（与 Network 失败同策略，谨慎）  
    3. 失败进度卡扫描器旁：若终态 succeeded 且 synced 空 → 横幅警告（不自动点确认）  
  - **不做**：改插件 success 判定；不把真有 synced 的成功改坏  
  - **验收**：单测覆盖空同步 closeout + 同句 continue 放行；有 synced 的成功路径文案与拦截行为不变  
  - **完成证据**：`isHollowCodingSuccess` / `codeFilesOnlyForSync`；closeout+dup-guard 单测；进度卡 `maybeHollowSuccess`；hard-pit 19+4；`build:client`；真成功路径不变  


- [x] **Q0-2　成功轮续改交接**  
  - **本仓做**：`buildSucceededParentHandoff`（已同步源码清单剔 \*.db + 勿重复造轮子）；`enrichContinueExecHandoff` 在成功父任务且 message 无交接时注入；`pre-execute` 已有注入点复用  
  - **不做**：改插件 compactParentHandoff；不重复灌导致 message 爆炸（有 marker 则跳过；文件列表上限与失败交接一致）  
  - **验收**：单测成功父任务交接；失败交接回归仍绿  
  - **完成证据**：`buildSucceededParentHandoff` / `buildHollowSuccessHandoff`；enrich 成功父注入；失败交接回归；hard-pit 20+4  


- [x] **Q0-3　工程短画像强制进写码消息**  
  - **本仓做**：确认 `attachCodingDirectoryPortrait` 在 begin/continue 的 execute（及必要的 pre-execute）路径稳定调用；提示词加一句「必须遵守消息内【工作区目录画像】，禁止套其它仓库」；无画像时不阻断写码（保持现状）  
  - **补全（2026-10-16）**：`formatCodingPortraitBlock`——栈 + 前端/页面根 + 后端/接口根 + 精简目录要点 + **通用禁改**（非 ERP）；`codingMessageWithCachedDirectory` 优先短画像，无 stack/layout 时回退原目录块；分诊仍用 `formatDirectoryBlock`  
  - **不做**：硬编码某一家 ERP 目录；不改画像扫描引擎语义（除非修明显 bug）  
  - **验收**：已有 `test_triage_pack` 相关用例仍过；补「栈/前后端根/禁改」单测；hard-pit 绿  
  - **完成证据**：`triage-pack.js` `formatCodingPortraitBlock`；`test_triage_pack`「写码短画像含栈…」；分诊全文目录回归；hard-pit 绿；未改 HITL/插件  

- [x] **Q0-4　结论可验收（不做全文缩短）**  
  - **本仓做**：成功 closeout / 写码路由提示：固定两句结构——「改了什么（文件或能力）」+「怎么验（打开哪页/点什么）」；失败仍用已有四类 closeout  
  - **不做**：P2-1 式大段缩短重写（用户已跳过）；不削弱失败分类  
  - **验收**：成功 closeout 单测含「验|打开|刷新」类指引；失败用例不回归  
  - **完成证据**：成功 closeout「请按下面方式验收…」；提示词 §4「改了什么+怎么验」；空同步假成功单测仍绿；hard-pit 20+4
