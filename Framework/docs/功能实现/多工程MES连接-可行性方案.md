# 多工程 MES 连接 · 可行性方案

> **状态**：**P0+P1 已落地**（2026-10-13）· 设置页改为「一项目一完整对接卡」（连接+文档+绑定工作区）；问数无工作区时行为与升级前一致  

> **目标**：一个 WorkBuddy 本机实例，能对接多个业务项目；**每个顶栏工作区对应一份「工程对接档案」**——档案里**一体包含** MES 地址账号 + 接口文档（api_docs）+ 可选字典，问数只认这一整份；**不改**单 bridge，**不拆**模型 Key。  
> **一体口径（最重要）**：**连接字段与文档导入不是两个功能、两张表，而是同一档案的上下两段。** 面向同一项目工作区；切换档案 = 地址和文档一起换；禁止「先配连接、文档另说」或「文档全局共用」。  
> **易操作原则**：用户配一份档案——「选/新建档案 → 绑当前工作区 → 填地址账号 → 在本档案内导入接口文档」；日常只切顶栏工作区。  
> **破窗**：若要改成「全局永远只有一套」或「连接与文档分库分页」，须用户明确允许后再改本文。

## 1. 一句话

**一个项目工作区 = 一份工程对接档案；档案 =（怎么连 MES）+（能调哪些接口文档）绑死在一起。**  
问数时：顶栏工作区 → 命中档案 → 用这份档案里的 Base URL **和** endpoints，没有「半套」。  
旧的全局 `mes` + `api_docs` + `data_dictionary` 自动升成第一份档案（`default`），零手工迁移。

小李顶栏在 `D:\proj\A`：问产量 → 只走 A 档案（A 的地址 + A 导过的 OpenAPI）。  
切到 `D:\proj\B`：整份换成 B 档案，**不会**出现「还连着 A 的地址却用 B 的文档」或反过来。  
模型 Key、本机登录、人员权限仍全局。

## 1.1 一体 vs 两张皮（必须对齐认知）

| 错误感觉（要避免） | 正确口径 |
|--------------------|----------|
| 上面是「MES 连接」，下面是「另一个文档功能」 | 下面导入区是**本档案的组成部分**，标题就写在本档案卡片里 |
| 先配好连接就能问数，文档以后再说 | **没导文档 = 这份档案未配完**；问数应提示补文档，而不是去借别的档案 |
| 多项目只复制 Base URL，文档继续用全局那一份 | **事故**：问数必串接口 |
| 设置里两个 Tab：连接 / 文档 | **禁止**：必须同一档案同一屏 |

实现上可以仍是 YAML 里 `mes` 与 `api_docs` 两个字段，但产品与 UI **只暴露一个对象**：「工程对接」列表里的一条。

## 2. 现状与缺口

| 项 | 现在 | 缺口 |
|----|------|------|
| 配置形态 | 全局一份 `mes` + `api_docs` + `data_dictionary`（数据上已挨着，产品上仍像两段） | 多项目时必须升成「多份一体档案」，不能只拆地址 |
| 设置页 | 同页上下：连接字段 + 接口文档导入 | 缺「面向哪个工作区」；多档案后须变成**一张档案卡**，而不是两个独立模块 |
| 问数 | `ask_api_route` 用文档匹配，再用 `mes` 发请求 | 缺按工作区解析**整份档案**；今日全局碰巧一体，多项目易被拆散 |
| 工程感知 | 顶栏工作区；`project-profile` 画像 | 画像与「工程对接档案」未挂钩 |
| 写码 data_contract | 来自全局 api_docs | 须跟工作区命中的**同一份档案**文档走 |

文档 checklist 已标 P2。本文收成 v1，并强调：**一体是产品真相，不是导入功能的附属说明。**

## 3. 可行性结论

| 维度 | 结论 | 说明 |
|------|------|------|
| 技术 | **高** | 一条 `items[]` 记录内嵌 `mes` + `api_docs` + `data_dictionary` + `workspace_roots`；导入 API 只写该 `id` |
| 兼容 | **高** | 现有三块整包升入 `default` 档案；顶层键做镜像，旧代码不断 |
| 操作 | **高** | 用户心智只有「这份工程怎么对接」；切工作区 = 换整份档案 |
| 风险 | **中低** | UI 若仍画成上下两个无关联卡片，会再次两张皮——布局必须合成一张档案卡 |

**建议做**：工作区 → 工程对接档案（连接∪文档一体）。  
**不建议做**：连接列表 + 另开「文档中心」；全局共用 api_docs；聊天里再选一遍 MES。

## 4. 产品规则（写死，避免扯皮）

1. **一份工程对接档案** = 展示名 + 绑定的工作区路径 + MES 地址鉴权 + **接口文档** + 可选字典。字段可分节展示，**对象不可拆库、不可拆页。**  
2. **面向工作区**：档案主键体验是「服务哪个工程目录」；Base URL / 文档都是该工作区问数用的材料。  
3. **同生同灭**：删档案 = 地址与文档一起删；复制档案可勾选「连同文档」；禁止只删文档留空壳当「还能问数」。  
4. **解析顺序**（问数 / 测连 / 文档导入与同步 / data_contract——全部针对**同一档案**）：  
   1. 当前工作区命中某档案的 `workspace_roots` → 用该档案全套  
   2. 否则 `active_profile_id`（回落档案）  
   3. 再否则 `id=default`  
   4. 仍没有 →「请先在设置里为当前工程配置对接档案」  
   5. 有档案但未导入有效 endpoints → 「请在本档案中导入接口文档」，**禁止**借用其它档案文档  
5. **商用 / 公共 / 视觉 Key**：全局，不进档案。  
6. **企业编码、文档源密码**：留在档案内。  
7. **权限**：沿用「连接配置」能力；能改档案就能改其中的地址与文档。  
8. **文档导入能力集（档案内必保）**：上传 / URL / 粘贴 / 预览确认 / 已接入数 / 按 source_url 同步——能力与现网一致，归属从「全局」改为「**本档案**」。

## 5. 数据模型（引擎）

逻辑上只有一种对象：**工程对接档案（profile）**。实现可用 `mes_connections` 键名，但注释与 API 按档案理解：

```yaml
# 兼容镜像：= 回落档案（active/default）的整包快照，旧代码只读顶层不断。
mes: { ... }
api_docs: { ... }
data_dictionary: { ... }

mes_connections:                 # 实现键名；产品称「工程对接」
  active_profile_id: default     # 无工作区命中时的回落档案
  items:
    - id: default
      name: A 厂生产             # 列表名 = 这份工程对接
      workspace_roots:           # 本档案服务哪些顶栏工作区
        - "D:/proj/A"
      # —— 以下同属本档案，禁止拆到别的 items 或全局另存一份真相 ——
      mes: { base_url, auth_type, username, password, enterprise_code, ... }
      api_docs: { endpoints, source_url, source_username, source_password, ... }
      data_dictionary: { ... }
```

**迁移（幂等）**：

1. `items` 已非空 → 跳过。  
2. 否则建 `id=default`，把现有 `mes` + `api_docs` + `data_dictionary` **整包**深拷进同一条（保持一体）。  
3. `code_dev.default_workspace` 非空则写入该档案 `workspace_roots`。  
4. `active_profile_id = default`，顶层三键镜像该档案。

**禁止**：删顶层镜像键（过渡期）。  
**禁止**：只升 `mes`、文档仍只留顶层——升级后立刻两张皮。  
**禁止**：多档案只存多套 Base URL、共用一份 api_docs。

## 5.1 档案内：接口文档（问数半壁江山）

现网导入链路全部保留，写入目标改为**当前编辑的档案**：

| 能力 | 一体行为 |
|------|----------|
| 上传 / URL / 粘贴 | 确认后写入**本档案** `api_docs` |
| 已接入 N 个 | 本档案统计；换列表项一起变 |
| 自动同步 | 本档案自己的 `source_url`，不刷别人 |
| 问数 | resolve 出档案后：用其 `api_docs` 匹配 + 用其 `mes` 请求（同一 id） |
| data_contract | 同一档案文档 |

**一张档案卡（P1 UI 硬要求）**：右侧不是「连接卡片 + 下面另起一个文档卡片」，而是：

1. 档案头：名称、绑定工作区、完整度（地址已填 / 文档已导入）  
2. 第一节「怎么连」：Base URL、账号、密码、企业编码、测试  
3. 第二节「能调哪些接口」：现网导入 UI（同卡内折叠或分区，**同一保存条**）  

切换左侧列表 = 换整张卡（两节内容一起换）。

**API**：导入类带 `profile_id`（或 `connection_id` 同义）；写 `items[id].api_docs` 并按需镜像顶层；**禁止**只改顶层。

## 6. 解析与调用（引擎）

```text
resolve_mes_profile(cfg, workspace: str | None) -> ProfileView
# ProfileView：id, name, workspace_roots, mes, api_docs, data_dictionary
# （实现文件名可用 mes_connection_resolve.py，对外语义是档案）
```

- 问数、探活、**文档导入/同步**、data_contract：**只许**拿完整 ProfileView，禁止一处读顶层 `mes`、另一处读顶层 `api_docs` 拼凑。  
- 设置页测试与导入：都针对**当前编辑档案 id**。  
- bridge 带上当前工作区路径即可。

验收：换工作区 → Base URL 与匹配到的接口 path **同时**换档；缺文档时提示补**本档案**，不串档。

## 7. 界面（易操作 · 一体感）

### 7.1 设置 → 工作助手 → MES 连接（一项目一卡，禁止「顶栏切换条 + 下方另卡」）

> **2026-10-13 UX 定稿**：不要单独红框「工程对接档案」切换条再配下方连接/文档卡——用户会觉得两套东西。  
> **正确**：堆叠多张完整对接卡；当前编辑卡展开全部字段；其它卡折叠摘要 +「编辑此卡」。

```text
[ 新增对接卡 ]

┌ A 厂生产（当前编辑）────────────────────────────┐
│ 绑定工作区：[下拉选择顶栏已开工程 ▼]               │
│ MES 连接：Base URL / 账号 / 密码 / 企业编码         │
│ 接口文档导入：上传 / URL / 粘贴 · 已接入 N         │
└────────────────────────────────────────────────┘
┌ B 厂试产 ──────────────────────────────────────┐
│ 地址 … · 文档未导入 · 未绑定工作区  [编辑此卡]   │
└────────────────────────────────────────────────┘

页脚统一：[重新加载]  [保存配置]  ← 整卡（连接+文档）落盘
问数：顶栏工作区路径 ↔ 卡上绑定路径 一一对应
```

操作路径：

1. **新增对接卡**（或点另一张「编辑此卡」）  
2. 在本卡内：**绑定工作区** → 填地址账号 → **导入接口文档**  
3. 底部 **保存配置**（仍整体保存，不拆两个保存）  
4. 以后只切顶栏工作区，问数按路径命中对应卡  

折叠卡副文案直接显示「地址 / 文档 N / 工作区」，避免用户以为「连上就算配完」。

### 7.2 禁止的 UI（会再次两张皮）

- **顶栏档案切换条 + 下方独立「怎么连 / 文档」卡**（已否决）  
- 连接一个 Tab、文档另一个 Tab  
- 文档导入挪到独立一级菜单  
- 聊天底栏再做 MES / 文档选择器  
- 两个保存按钮（「只存连接」「只存文档」）——**必须页脚统一「保存配置」**  

### 7.3 文案

- 未绑定工作区：可保存，问数提示绑定。  
- 已绑定未导文档：「请在对接卡「xxx」中导入接口文档」。  
- 目录冲突：写明已占用的**卡名**。

## 8. 分阶段交付（靠谱节奏）

### P0 · 兼容底座（一体数据结构先落地）

- 迁移：**mes ∪ api_docs ∪ dictionary 进同一 default 档案**  
- `resolve_mes_profile`：问数 / 探活 / 导入 / 同步 **整包**读取  
- 顶层三键镜像  
- 单测：整包迁移、禁止拼凑读写、导入进档案后问数命中 endpoints  

**验收**：老 UI 暂可不改，行为与现网一致，且配置里已是一体档案。

### P1 · 多档案可用（一张卡露出）

- 左侧档案列表 + 右侧**一张档案卡**（怎么连 + 能调哪些接口）  
- 绑定工作区；单一「保存本档案」  
- 完整度：地址 / 文档；列表显示文档条数  
- 切换档案 = 两节一起换，互不覆盖  

**验收**：两份档案、两个工作区；换顶栏后地址与接口 path 同时换；缺文档只提示本档案。

### P2 · 打磨（可选）

- 问数角标：「档案 A 厂生产 · 42 接口」  
- 复制档案（默认连同文档）  
- 未绑定软提示走回落档案

## 9. 非目标（本期明确不做）

| 不做 | 原因 |
|------|------|
| 按登录账号隔离 MES 密码 | 本机信任模型 |
| 公网多租户 | 另立项 |
| 部署 SSH / 写码 Key 进档案 | 职责不同 |
| 改 DSH 插件 / 第二 bridge | 铁律 |
| 连接与文档分 Tab、分菜单、分保存 | **破坏一体，明确禁止** |
| 全局共用一份 api_docs | 问数串接口，等于没做 |
| 「先做多连接，文档以后再挂」 | **禁止分期拆开**；P0 就必须整包 |

## 12. 验收清单（P1 完成才算交付）

1. 老配置升 `default` 后，**地址与原文档同在一条档案**，问数不变。  
2. 新建档案 B：绑定工作区 B，**同卡**导入 B 文档；切 A/B 工作区后，Base URL **与**匹配 path 同档切换。  
3. 改 A 的文档，B 的「已接入 N」不变。  
4. 页脚：工作区 → 档案名（一体），不是只写「连接名」。  
5. 未导文档：提示补**本档案**文档，不借用其它档案。  
6. 目录冲突、刷新不丢、密钥脱敏。  
7. 上传 / URL / 粘贴 + 测试连接仍在**同一张档案卡**内可用。  
8. UI 无「连接 / 文档」双 Tab；仅一个「保存本档案」。  
9. 入口仍是 **http://127.0.0.1:3081**；无新业务 Cordis 包。

## 14. 一句话结论

**一个工作区 ↔ 一份工程对接档案；档案里地址和接口文档天生一体。**  
问数只认这一整份；设置里也是一张卡配完，而不是「连接一套、文档另一套」。  
P0 先把数据结构绑死，P1 再露出多档案列表——从一开始就不允许两张皮。
